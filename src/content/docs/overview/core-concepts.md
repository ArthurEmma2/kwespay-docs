## Account and merchant

An **account** is the login you create on the dashboard. An account owns one or more **merchants** (called vendors in the API). Each merchant has a **vendor ID**, a UUID you pass as `vendorIdentifier` or `vendorId`, along with:

- The networks it has enabled.
- The tokens it accepts.
- A receiving wallet for each chain family it uses: one EVM address, one Sui address and one Stellar address.

A merchant can only receive payments on a network it has enabled and for which it has a receiving wallet of the right family.

## API key

An **API key** authorises payment requests. It is sent in the `X-API-Key` HTTP header. Keys belong to the account, so one key can serve several of the account's merchants. A key can be limited to particular networks and tokens, and it can expire. See [Authentication](/api/authentication/).

## Quote

A **quote** fixes the price of one payment. It records the fiat amount and currency, the token, the network and the resulting token amount. A quote lasts **10 minutes** and can be used for **one** transaction.

## Transaction

A **transaction** is created from a quote and a payer's wallet address. It carries the signed terms the wallet submits and a **transaction reference**, the UUID you use to track and verify the payment. A transaction that is not paid expires after **15 minutes**.

## Payment ID

The **payment ID** (`paymentIdBytes32`) is the identifier the contract stores to prevent the same payment from being executed twice. It is generated by the API and is part of the signed terms.

## Base units

Amounts are exchanged as strings of integer **base units**, the smallest unit of the token on its network. 10 USDC is `10000000` on EVM networks (6 decimals) and `100000000` on Stellar (7 decimals). Use `displayAmount` for human-readable output and keep base units for anything you compare or sign.

| Token | Decimals |
| --- | --- |
| ETH, MATIC, LSK, ARB, MEZO, BTC on Mezo, DAI, MUSD | 18 |
| USDC, USDT, USDC.e, USDbC on EVM networks | 6 |
| USDC on Stellar | 7 |
| XLM | 7 |
| SUI | 9 |

## Amount, total and fee

- `amountBaseUnits` is what the merchant receives.
- `totalBaseUnits` is what the customer pays: the amount plus the platform fee.
- The fee is `totalBaseUnits − amountBaseUnits`. Read it from the API response instead of computing it yourself. See the [fee model](/contracts/fee-model/).

## Deadline

The **deadline** is the last moment the signed terms are valid on-chain. On EVM networks and Sui it is a Unix timestamp in seconds. On Stellar it is a **ledger sequence number**, not a timestamp.

## Status

A transaction moves through these statuses:

| Status | Meaning |
| --- | --- |
| `pending` | Created and signed, not yet reported as broadcast |
| `processing` | A transaction hash has been reported and is being confirmed |
| `completed` | Paid in full and confirmed on-chain |
| `underpaid` | Confirmed on-chain, but the merchant received less than quoted |
| `overpaid` | Confirmed on-chain, but the merchant received more than quoted |
| `failed` | A payment event did not match the expected merchant wallet or token |
| `expired` | The 15-minute window passed. Usually unpaid, but check `blockchainHash`. See [Payment statuses](/merchants/payment-statuses/) |
| `refunded` | Paid, then refunded |

Only KwesPay's chain listeners and reconciler can set `completed`, `underpaid` or `overpaid`. See [Payment statuses](/merchants/payment-statuses/).
